## Sensitive data goes through the site's server

Files in the `documents` bucket, changes to `documents` rows, staff reads of the full
application (SSNs) and new leads go through the site's own server routes (`/api/documents`,
`/api/documents/upload`, `/api/application-details`, `/api/application/start`), not the
Supabase client in the browser. Leads are written only by the server: the application's first
screen posts to `/api/application/start` (`src/lib/application-start.server.ts`), which checks
the rep and the per-network limit before it saves the lead. Do not add another public route that
inserts into `leads`: a lead with a rep's `ref` sends that rep a "Started on your link" alert. The database refuses the browser for those once the server
stamp is switched on (`docs/database.md`, "Through the site's server"), so a new screen that
calls `supabase.storage` or writes `documents` from the browser gets nothing back.

## Run the checks before calling anything done

After building a feature, fixing a bug or changing a dependency, run all four and keep them green:

- Types: `bunx tsc --noEmit -p .`
- Lint and formatting: `bunx eslint . --quiet`
- Build: `bun run build`
- Tests: `deno test --node-modules-dir=none tests/` (every file in `tests/`, not a chosen few)

The same steps run on every pull request and every change to main (`.github/workflows/checks.yml`).
A change that adds behaviour adds a test for it in `tests/`. Files in `src/integrations/supabase/`
are generated by Lovable, so prettier skips them.

## Website tracking

Load Metricool's browser tag from the root head using `src/lib/metricool.ts` so shared page renders do not initialize a second tracker.
The tag is an outside company's script: it loads on the marketing pages listed in that file only, never on the application, an application link, Offer Check, sign-in, the account page or the staff portal. Do not widen the list without Asad's say-so.
A script the host puts into the published page counts as an outside tracker under this rule too, even though no file here loads it. Lovable's published-site analytics (a `/__l5e/` script with click autocapture) was on every page on 2026-11-27, the SSN, documents and staff pages included; turning it off or fencing it is Asad's call. Do not turn on or widen a host script without his say-so, and `/privacy` must name any that runs. Check the live HTML with `curl -s https://getlamp.app/application | grep -a __l5e` (the page comes back compressed, so a plain grep misses the tag).

## Secrets stay out of the repo

The repo is public and git keeps every old version of a file. Only `VITE_` publishable values (the Supabase project id, URL and publishable key the browser already gets) may be committed, in `.env` or anywhere else. Server secrets (`SUPABASE_SERVICE_ROLE_KEY`, `LAMP_SERVER_STAMP`, `LOVABLE_CRON_SECRET`, `ANTHROPIC_API_KEY`, `DISCORD_BOT_TOKEN`, `GOOGLE_CLIENT_SECRET` and the rest the server reads through `env()`) live in Lovable Cloud's secrets only. Never commit an `sb_secret_` key, a `service_role` token or a `postgres://` URL. One that was ever pushed must be rotated, not just deleted.
